# Плагины JetBrains на Flutter

Лабораторная 3, веха **В2 «Данные»**: моки из ЛР2 заменены данными из сети.
Курс кроссплатформенной разработки, группа ПИН-252т.

Каталог плагинов [JetBrains Marketplace](https://plugins.jetbrains.com):
список, деталь плагина и страница вендора. Это то же приложение, что в ЛР1 на
Compose Multiplatform ([JetBrains-Plugins](https://github.com/ritabokach/JetBrains-Plugins)):
тот же домен и те же экраны, только на Flutter. Данные приходят из открытого
API маркетплейса, ключ не нужен.

Проект создан командой `flutter create` для web, Android, Windows, macOS и
Linux. Первый коммит — её вывод без правок, всё остальное написано поверх.

Flutter 3.47, Dart 3.13, flutter_bloc 9, go_router 18, dio 5, json_serializable 6.

## Запуск

```bash
flutter pub get                                   # заодно генерирует код локализации
flutter run -d chrome --web-browser-flag=--disable-web-security   # браузер, см. «CORS» ниже
flutter run -d chrome --dart-define=LOCALE=en     # тот же интерфейс на английском
flutter run -d macos                              # второй таргет
```

После правки DTO код `*.g.dart` генерируется заново. Он лежит в git, поэтому
после клона проект собирается и без этого шага:

```bash
dart run build_runner build --delete-conflicting-outputs
```

`--dart-define=LOCALE=en` меняет язык только у приложения, настройки системы и
браузера остаются как были. Без флага язык берётся из системы.

Собирается и под Android (`flutter build apk`). Windows и Linux созданы
визардом, но на них не проверялись: под рукой только Mac.

## Как разложен код

```
lib/
  main.dart                 язык из --dart-define=LOCALE
  app.dart                  корень: репозиторий, Cubit списка и темы, MaterialApp.router
  common/
    navigation/             адреса экранов и go_router
    theme/                  AppColors, AppTheme, ThemeCubit
    network/                DioClient (базовый адрес, таймауты, лог в debug), LoadException
    widgets/                шапка с переключателем темы, ширина контента, текст-заглушка, ошибка с «Повторить»
  features/plugin/
    domain/                 PluginModel, VendorModel, IPluginRepository. Без Flutter
    data/
      api/                  PluginApi: один метод на один адрес сервера, отдаёт DTO
      dto/                  DTO на json_serializable и сгенерированные *.g.dart
      data_sources/         IPluginDataSource и сетевая реализация: DioException → LoadException
      mappers/              DTO → модели domain
      plugin_repository.dart  репозиторий на датасорсе
    presentation/
      bloc/list/            PluginListCubit и его состояние
      bloc/detail/          PluginDetailBloc, события и состояния
      bloc/vendor/          VendorBloc, события и состояния
      utils/                расширения для показа: загрузки 37.8M, оценка, ссылки, хост сайта
      view/                 экраны списка, детали и вендора
      view/widgets/         карточка, аватар, бейджи, теги, поиск, строки фактов

tool/check_arb.dart         сверка ключей между локалями
```

Фича одна — `plugin`. Вендор существует в приложении только как автор
плагина, и страница вендора — это тоже список плагинов, поэтому отдельной фичи
у него нет.

## Решения, которые видно не сразу

**State manager — flutter_bloc.** У списка Cubit, у детали и у вендора Bloc.
Список живёт всё время работы приложения и откликается на два действия:
загрузиться и найти. Для этого хватает публичных методов `load()` и
`search(query)`. Деталь и вендор открываются по id и загружаются один раз. Их
событие `PluginDetailOpened` / `VendorOpened` называет то, что уже случилось, а
состояние — sealed-класс `Loading | Loaded | NotFound`. `switch` в экране
обязан разобрать все три варианта, иначе код не скомпилируется.

**Где живут Cubit и Bloc.** Репозиторий и `PluginListCubit` созданы в
`app.dart` через `RepositoryProvider` / `MultiBlocProvider`, рядом с
`ThemeCubit`. Поэтому список, запрос и тема не теряются, пока открыта деталь.
Bloc детали и Bloc вендора создаёт сам экран: у каждой открытой страницы свой
Bloc, и он закрывается, когда страницу снимают со стека. Роутер Bloc не
создаёт. Cubit и Bloc ничего не знают про навигацию: переход делает виджет
через `context.push(...)`.

**Состояние списка.** Тоже sealed-класс: `Loading | Loaded | Failure`, а
запрос лежит в базовом классе, чтобы поле поиска и проверка гонки видели его в
любом варианте. Начальное состояние — `Loading`, поэтому экран отличает «ещё
загружается» (индикатор) от пустого ответа. У `Loaded` два пустых случая:
пустой каталог без запроса («В каталоге пока нет плагинов») и пустой результат
поиска («По запросу … ничего не нашлось»). Если репозиторий бросит
`LoadException`, Cubit выдаст `Failure` с этой ошибкой, и экран покажет
сообщение с кнопкой «Повторить», которая заново вызывает `load()` с тем же
запросом. У `Loaded` есть ещё `hasMore`, `isLoadingMore` и `loadMoreError` для
подгрузки страниц: если следующая страница не пришла, загруженное остаётся, а
внизу появляется ошибка с «Повторить». У детали и вендора к `Loading | Loaded |
NotFound` добавился `Failure`, а к событию `…Opened` — `…Retried` для кнопки
повтора.

**Гонка в поиске.** `search()` сразу кладёт запрос в состояние, а результат
принимает, только если запрос за время ожидания не поменялся: ответ на `ko` не
должен затереть уже пришедший ответ на `kot`. После `await` проверяется ещё и
`isClosed`. Подгрузка страницы принимает ответ, только если состояние всё ещё
то, что она сама выставила. Bloc детали и вендора при закрытии сам отменяет
обработчик, поэтому ответ, пришедший после «назад», никуда не пишется.

**Маршрут — путь с id.** `/plugin/:id` и `/vendor/:slug` вложены в `/`, поэтому
даже при открытии по ссылке под деталью лежит список и стрелка «назад»
работает. Модель через `extra` не передаётся: id приходит из адреса, а экран
сам загружает запись. В адрес можно вписать что угодно, поэтому у детали и
вендора есть состояние `NotFound`, а у роутера — свой экран «Такой страницы
нет» на русском вместо стандартного английского. `optionURLReflectsImperativeAPIs`
включён, иначе после `push` в адресной строке оставался бы `/`.

**Анимация перехода.** Новая страница въезжает справа, а предыдущая немного
сдвигается влево. При возврате Flutter проигрывает ту же анимацию в обратную
сторону: страница уезжает вправо, и возврат выглядит как возврат. В CMP для
этого пришлось вручную задавать три спецификации `NavDisplay`, здесь хватает
одной `CustomTransitionPage`.

**Отдельных моделей для экрана нет.** В CMP у каждого экрана были свои
`PluginCardUi` / `PluginDetailUi` и маппер в них. Здесь экран получает
`PluginModel` как есть, а форматирование для показа (`downloadsLabel`,
`ratingLabel`, `links(l10n)`, `siteHost`) вынесено в расширения в
`presentation/utils`. Поэтому вендор вложен в плагин целиком
(`plugin.vendor.name`), а не лежит в нём числом `vendorId`: карточке нужно имя
вендора, и ей не придётся ходить за ним в репозиторий. Ответ
`/api/plugins/{id}` тоже отдаёт вендора объектом.

**Цвет бейджа модели распространения не зависит от темы.** Цвета бейджей лежат
в `AppColors`, но в `ColorScheme` не попадают: зелёный означает «бесплатный», а
не «светлое оформление». Остальные виджеты берут цвета только из
`Theme.of(context).colorScheme`, поэтому тёмная тема задевает все поверхности.
Палитра светлой и тёмной темы та же, что в CMP.

**Поле поиска хранит контроллер у себя.** `TextEditingController` создаётся
один раз в `initState` с текущим запросом из Cubit, а освобождается в
`dispose`. Крестик очищает и поле, и запрос: `controller.clear()` не вызывает
`onChanged`, поэтому пустой запрос отправляется отдельно.

**Узкое окно.** Карточка переносит теги и строку «загрузки · оценка» через
`Wrap`, длинные имена обрезаются многоточием. На широком окне содержимое
ограничено 720 px и стоит по центру, чтобы строки не растягивались на весь
монитор.

## Про данные

Цепочка: **PluginApi → NetworkPluginDataSource → PluginRepository → Cubit/Bloc
→ экран.** Собирается она только в `app.dart`, там же создаётся единственный
`Dio`. Базовый адрес `https://plugins.jetbrains.com/api` записан только в
`DioClient`.

| Экран | Запросы |
|---|---|
| Список | `/searchPlugins?orderBy=downloads&offset=N&max=20`: самые популярные сверху, следующая страница при докрутке |
| Поиск | `/searchPlugins?search=…&offset=N&max=20`, в порядке релевантности |
| Деталь | `/plugins/{id}` и `/plugins/{id}/rating` параллельно |
| Вендор | `/vendors/{name}`, потом `/vendors/{name}/plugins` |

Датасорс ловит `DioException` и ошибки разбора и бросает свой sealed
`LoadException`: нет связи, таймаут, 404, ошибка сервера, непонятный ответ.
Cubit и Bloc ловят только его и кладут в состояние `Failure`. Ошибка никогда не
превращается в пустой список: без сети экран показывает ошибку, а не «ничего не
нашлось». 404 у детали и вендора репозиторий переводит в `null`, и экран
показывает «такого нет» без кнопки повтора.

**Что пришлось поменять из-за API.** У вендора на сервере нет числового адреса:
`/vendors/1` отвечает 404, а `/vendors/JetBrains` работает. Поэтому маршрут
вендора теперь `/vendor/:slug`, где slug — поле `name` из ответа сервера, а в
`VendorModel` вместо числового `id` поле `slug`. В плагинах из списка вендор
урезанный, только имя, поэтому `slug` может быть `null`. Деталь всегда берёт
вендора из полного ответа, и там он есть.

Оценки нет в ответе `/plugins/{id}`. Её отдаёт `/plugins/{id}/rating` голосами
по звёздам, и репозиторий считает среднее. В списке сервер присылает готовую
оценку, поэтому во втором знаке после запятой они могут разойтись.

**CORS.** Заголовок `Access-Control-Allow-Origin` маркетплейс отдаёт только
у `/searchPlugins`. У `/plugins/{id}` и `/vendors/…` его нет, поэтому в обычном
Chrome список и поиск работают, а деталь и вендор показывают «Нет связи с
сервером». Это ограничение сервера, а не приложения: на macOS и Android CORS
нет, и там работает всё. Для браузера Flutter запускает Chrome с флагом
`--disable-web-security` (команда в разделе «Запуск»): это отдельный профиль
Chrome, обычный браузер он не задевает.

Данные каталога английские, и это не недоделка: переводится интерфейс, а не
содержимое. Теги, имена плагинов и вендоров приходят из API как есть.

В `IPluginRepository` по-прежнему два метода: `getPlugins` для пустого
запроса и `searchPlugins` для поиска, выбирает между ними Cubit. Оба теперь
постраничные. Сейчас `/searchPlugins` отдаёт каталог и без параметра `search`,
поэтому `getPlugins` — тот же адрес без него, но с сортировкой по загрузкам. Больше 24 записей за раз сервер
не отдаёт, страница — 20.

Иконки плагинов в ответе — SVG, поэтому вместо них по-прежнему заглушка с
первой буквой имени.

## Подписи

Всё, что видит пользователь, лежит в `lib/l10n/*.arb`, включая заголовок
вкладки. Ключи те же, что в `strings.xml` CMP-версии. Код `AppLocalizations`
генерирует gen_l10n при `flutter pub get`, в git он не лежит.

Если ключ забыт во втором языке, gen_l10n не выдаёт ошибку, а подставляет
русский текст. Поэтому есть `tool/check_arb.dart` из шаблона ПЗ2: он сверяет
ключи и плейсхолдеры и возвращает код 1, если языки разошлись. Подписи, по
ошибке написанные прямо в виджете, ищутся так:

```bash
git grep -nE "Text\(\s*'" -- lib     # пустой вывод — всё в порядке
```

## Чего здесь сознательно нет

Тема и язык живут в памяти сессии: на диск не сохраняется ничего, кэша
ответов тоже нет. Избранного, DI-контейнера, use case'ов, библиотек пагинации
и тестов нет — по заданию это не нужно или относится к следующим вехам.
